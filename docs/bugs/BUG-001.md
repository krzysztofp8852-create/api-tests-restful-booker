# BUG-001: Missing required booking fields return 500 instead of 4xx

| Field | Value |
|---|---|
| ID | BUG-001 |
| Title | Missing `firstname` / `lastname` causes Internal Server Error |
| Severity | Major |
| Priority | P2 |
| Status | Open |
| Environment | Restful Booker · `https://restful-booker.herokuapp.com` |
| Endpoint | `POST /booking` |
| Found in | TC-010, TC-018 |
| Date | 2026-08-13 |
| Author | Krzysztof Pabich |

## Summary

Omitting required string fields (`firstname` or `lastname`) makes the API respond with **500 Internal Server Error** instead of a client error. The server should reject invalid payloads without crashing.

## Preconditions

- API is up (`GET /ping` → 201)

## Steps to reproduce

1. `POST /booking` with JSON **without** `firstname`:

```json
{
  "lastname": "Tester",
  "totalprice": 120,
  "depositpaid": true,
  "bookingdates": {
    "checkin": "2026-09-01",
    "checkout": "2026-09-05"
  }
}
```

2. Repeat with `firstname` present and `lastname` omitted (TC-018).

## Expected result

HTTP **400** (or another 4xx). Body explains which field is missing. No `bookingid`. No 5xx.

## Actual result

- HTTP status: **500**
- Body: `Internal Server Error` (`text/plain`)

## Evidence

- [x] Reproduced at least twice: yes (firstname missing and lastname missing)
- [x] Date/time of reproduction: 2026-08-13
- Covered by Newman: `TC-010 POST Create booking — missing firstname`, `TC-018 POST Create booking — missing lastname`

## Workaround

Validate required fields on the client before calling the API.

## Notes

Same 500 for both missing `firstname` and missing `lastname`. Suggests unhandled exception during persistence rather than input validation.
