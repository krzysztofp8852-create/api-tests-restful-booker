# BUG-002: Booking created when checkout is before check-in

| Field | Value |
|---|---|
| ID | BUG-002 |
| Title | Booking created when checkout is before check-in |
| Severity | Major |
| Priority | P2 |
| Status | Open |
| Environment | Restful Booker · `https://restful-booker.herokuapp.com` |
| Endpoint | `POST /booking` |
| Found in | TC-011 |
| Date | 2026-08-13 |
| Author | Krzysztof Pabich |

## Summary

API accepts a booking whose `checkout` date is earlier than `checkin` and returns **200** with a new `bookingid`. A reservation with inverted dates should be rejected.

## Preconditions

- API is up (`GET /ping` → 201)

## Steps to reproduce

1. `POST /booking` with JSON:

```json
{
  "firstname": "Krzysztof",
  "lastname": "Tester",
  "totalprice": 50,
  "depositpaid": true,
  "bookingdates": {
    "checkin": "2026-09-10",
    "checkout": "2026-09-01"
  }
}
```

2. Observe status and body.

## Expected result

Client error (4xx). Body explains that checkout must be after checkin. No `bookingid`.

## Actual result

- HTTP status: **200**
- Body (trimmed):

```json
{
  "bookingid": 535,
  "booking": {
    "firstname": "Krzysztof",
    "lastname": "Tester",
    "totalprice": 50,
    "depositpaid": true,
    "bookingdates": {
      "checkin": "2026-09-10",
      "checkout": "2026-09-01"
    }
  }
}
```

## Evidence

- [x] Reproduced at least twice: yes
- [x] Date/time of reproduction: 2026-08-13
- Covered by Newman: `TC-011 POST Create booking — checkout before checkin`

## Workaround

Client-side validation of dates before calling the API.

## Notes

Inverted dates are persisted as sent. There is no server-side range check on `bookingdates`.
