# BUG-002: Booking created when checkout is before check-in

| Field | Value |
|---|---|
| ID | BUG-002 |
| Title | Booking created when checkout is before check-in |
| Severity | Major |
| Priority | P2 |
| Status | Open |
| Environment | Restful Booker · `https://restful-booker.herokuapp.com` |
| Endpoint | `POST /booking` |
| Found in | TC-011 |
| Date | 2026-08-13 (re-verified 2026-09-09) |
| Author | Krzysztof Pabich |

## Summary

The API accepts a booking whose `checkout` date is earlier than `checkin` and returns **200** with a new `bookingid`. A reservation with an inverted date range should be rejected.

## Preconditions

- API is up (`GET /ping` → 201)

## Steps to reproduce

1. `POST /booking` with JSON:

```json
{
  "firstname": "Krzysztof",
  "lastname": "Tester",
  "totalprice": 50,
  "depositpaid": true,
  "bookingdates": {
    "checkin": "2026-09-29",
    "checkout": "2026-09-10"
  }
}
```

2. Observe status and body.

## Expected result

Client error (4xx). Body explains that checkout must be after checkin. No `bookingid`.

## Actual result

- HTTP status: **200**
- Body (trimmed):

```json
{
  "bookingid": 535,
  "booking": {
    "firstname": "Krzysztof",
    "lastname": "Tester",
    "totalprice": 50,
    "depositpaid": true,
    "bookingdates": {
      "checkin": "2026-09-29",
      "checkout": "2026-09-10"
    }
  }
}
```

## Evidence

- [x] Reproduced at least twice: yes
- [x] Date/time of reproduction: 2026-09-09
- Covered by Newman: `TC-011 POST Create booking — checkout before checkin` — the test asserts that the stored `checkout` timestamp is strictly earlier than `checkin`, so it will start failing the moment the range check is added

## Workaround

Client-side validation of the date range before calling the API.

## Notes

The inverted range is persisted exactly as sent — there is no server-side range check on `bookingdates`. Related to [BUG-004](BUG-004.md): the same field pair also accepts values that are not dates at all.
