# BUG-003: Wrongly typed booking fields are silently coerced instead of rejected

| Field | Value |
|---|---|
| ID | BUG-003 |
| Title | `totalprice` and `depositpaid` accept strings and are silently coerced |
| Severity | Minor |
| Priority | P3 |
| Status | Open |
| Environment | Restful Booker · `https://restful-booker.herokuapp.com` |
| Endpoint | `POST /booking` |
| Found in | TC-019, TC-039 |
| Date | 2026-08-13 (re-verified 2026-09-09) |
| Author | Krzysztof Pabich |

## Summary

`POST /booking` accepts strings where the documented type is a number or a boolean and creates the booking anyway (**200**). The values are coerced silently: `"totalprice": "abc"` becomes `null`, `"depositpaid": "yes"` becomes `true`.

## Preconditions

- API is up (`GET /ping` → 201)

## Steps to reproduce

1. `POST /booking` with a non-numeric price (TC-019):

```json
{
  "firstname": "Krzysztof",
  "lastname": "Tester",
  "totalprice": "abc",
  "depositpaid": true,
  "bookingdates": { "checkin": "2026-09-16", "checkout": "2026-09-20" }
}
```

2. `POST /booking` with a non-boolean deposit flag (TC-039):

```json
{
  "firstname": "Krzysztof",
  "lastname": "Tester",
  "totalprice": 120,
  "depositpaid": "yes",
  "bookingdates": { "checkin": "2026-09-16", "checkout": "2026-09-20" }
}
```

## Expected result

HTTP **400** for both. Body states which field has the wrong type. No `bookingid`.

## Actual result

| Case | Sent | Status | Stored as |
|---|---|---|---|
| TC-019 | `"totalprice": "abc"` | **200** | `"totalprice": null` |
| TC-039 | `"depositpaid": "yes"` | **200** | `"depositpaid": true` |

Response body for TC-019 (trimmed):

```json
{
  "bookingid": 547,
  "booking": {
    "firstname": "Krzysztof",
    "lastname": "Tester",
    "totalprice": null,
    "depositpaid": true,
    "bookingdates": { "checkin": "2026-09-16", "checkout": "2026-09-20" }
  }
}
```

## Evidence

- [x] Reproduced at least twice per case: yes
- [x] Date/time of reproduction: 2026-09-09
- Covered by Newman: `TC-019 POST Create booking — totalprice as string`, `TC-039 POST Create booking — depositpaid as string`

## Workaround

Send correctly typed values from the client, and treat a `null` `totalprice` in a response as corrupt data.

## Notes

Two different failure modes from the same missing type check: `totalprice` loses the value (a booking without a price), while `depositpaid` gains a value the caller never sent — coercing any non-empty string to `true` means `"no"` and `"false"` also become `true`. Same root cause family as [BUG-004](BUG-004.md) and [BUG-005](BUG-005.md): the create path performs no schema validation on the payload.
