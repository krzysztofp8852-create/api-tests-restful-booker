# BUG-005: Negative totalprice is accepted and persisted

| Field | Value |
|---|---|
| ID | BUG-005 |
| Title | `POST /booking` accepts a negative `totalprice` |
| Severity | Minor |
| Priority | P3 |
| Status | Open |
| Environment | Restful Booker · `https://restful-booker.herokuapp.com` |
| Endpoint | `POST /booking` |
| Found in | TC-032 |
| Date | 2026-09-09 |
| Author | Krzysztof Pabich |

## Summary

`POST /booking` performs no range check on `totalprice`. A negative amount is accepted with **200** and stored exactly as sent, so a booking can carry a price of `-500`.

## Preconditions

- API is up (`GET /ping` → 201)

## Steps to reproduce

1. `POST /booking` with JSON:

```json
{
  "firstname": "Krzysztof",
  "lastname": "Tester",
  "totalprice": -500,
  "depositpaid": true,
  "bookingdates": {
    "checkin": "2026-09-16",
    "checkout": "2026-09-20"
  }
}
```

## Expected result

HTTP **400**. Body states that `totalprice` must be zero or greater. No `bookingid`.

## Actual result

- HTTP status: **200**
- Body (trimmed):

```json
{
  "bookingid": 4673,
  "booking": {
    "firstname": "Krzysztof",
    "lastname": "Tester",
    "totalprice": -500,
    "depositpaid": true,
    "bookingdates": { "checkin": "2026-09-16", "checkout": "2026-09-20" }
  }
}
```

## Evidence

- [x] Reproduced at least twice: yes
- [x] Date/time of reproduction: 2026-09-09
- Covered by Newman: `TC-032 POST Create booking — negative totalprice`

## Workaround

Validate the amount on the client, and reject non-positive prices before they reach billing.

## Notes

Severity is Minor because the demo API has no payment flow, but in a real booking system a negative price is a refund the caller never authorised. The type is correct here, so this is a range check, not the coercion problem in [BUG-003](BUG-003.md) — a complete fix needs both.
